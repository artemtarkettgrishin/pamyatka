# Обновление «Памятки» v10 → v11

Это обновление механизма синхронизации для уже работающей версии 10.
Google Таблица остаётся прежней: тот же файл, те же листы К10, ID и данные.
Дизайн, мобильное расположение таблицы и редакторы сохранены.
Архив подготовлен отдельно. Ваша таблица, Apps Script и GitHub при подготовке не изменялись.

## 1. Перед обновлением

1. Дождитесь статуса «Записано в таблицу» на устройствах администраторов. На время обновления не вносите новые правки. Обычный просмотр можно оставить.
2. Сохраните текущий код Apps Script в текстовый файл на компьютере. Запишите номер текущей версии развёртывания и действующий адрес `https://script.google.com/macros/s/.../exec`.
3. На GitHub откройте существующий репозиторий → Code → Download ZIP. Это резерв именно вашей установленной версии, включая адрес подключения и возможные самостоятельные изменения.
4. Для дополнительной копии данных можно скачать Google Таблицу через Файл → Скачать → Microsoft Excel. Загружать эту копию обратно не требуется.

Не создавайте новую рабочую таблицу и новый проект Apps Script. Не очищайте листы. Не импортируйте демонстрационные данные из архива.

## 2. Сначала обновите серверный код

Этот этап работает даже со старой страницей приложения. Он включает пакетное получение свойств листов и пакетную работу с кэшем.

1. Откройте действующую «Памятка в10» → Расширения → Apps Script.
2. В распакованном архиве откройте `Backend-v11.gs` через Блокнот или редактор кода. Скопируйте весь текст.
3. В Apps Script найдите файл, куда раньше вставляли полный серверный код, обычно `Код.gs` или `Backend.gs`. Замените его содержимое целиком. Не добавляйте вторую копию рядом со старым кодом.
4. Сохраните проект. Существующие настройки проекта, сервис Google Sheets API, пароль ADMIN_PASSWORD, SESSION_SECRET_V8, манифест и триггеры оставьте прежними.
5. **Не запускайте `setup()` или `installWorkbook()`.** Для обновления работающей таблицы они не нужны. Имена обработчиков существующих триггеров сохранены.
6. При желании выберите сверху функцию `checkV11` → Выполнить. Она только читает каталог и пишет результат в журнал выполнения. Ожидается `engineVersion:11`, текущая версия данных, количество разделов и товарных строк. Если есть ошибка, остановитесь и сохраните её текст; не запускайте установку для её исправления.
7. Нажмите Развернуть / Начать развертывание → Управление развертываниями. Выберите **существующее** веб-приложение → карандаш → Версия → Новая версия → Развернуть. Не создавайте отдельное новое развёртывание. Адрес `/exec` должен остаться прежним.
8. Откройте прежнее приложение и загрузите данные. Проверьте знакомую коллекцию и несколько цен. Новая серверная версия совместима со старым приложением.

Если редактор показывает несколько серверных файлов и код был вручную разделён между ними, не вставляйте ещё один полный Backend поверх: сначала нужно сопоставить текущие файлы. Приведённый способ рассчитан на прежнюю установку одного объединённого скрипта из архива v10.

Сохранение кода меняет также код, который выполняют установленные триггеры; публикация новой версии обновляет веб-приложение. Поэтому при откате важно восстановить оба.

## 3. Затем обновите приложение на GitHub

Перед этим посмотрите Settings → Pages → Build and deployment → Source в текущем репозитории. Существующий способ публикации менять не нужно.

### Если Source = GitHub Actions

Используйте исходники из этого архива. Важное исключение: **сохраните действующий `src/config.ts` из вашего репозитория**, особенно строку `gasUrl`. В универсальном архиве этот адрес пустой, потому что он индивидуален для вашей установки.

1. Скачайте ваш текущий `src/config.ts` с GitHub и поместите его в папку `src` распакованного обновления вместо универсального файла.
2. На GitHub в существующем репозитории выберите Add file → Upload files.
3. Загрузите папки `src`, `shared`, `server`, `scripts`, `public`, `tests`, `rollback` из обновления, а также `package.json`, `package-lock.json`, `tsconfig.json`, `vite.config.ts` и корневой `index.html`. Сохраните пути папок: например, `src/App.tsx` должен остаться именно там.
4. Существующий `.github/workflows/deploy.yml` менять не требуется. Не загружайте `node_modules` и сам ZIP вместо распакованных файлов. Папки `tests` и `rollback` нужны для автоматических проверок сборки.
5. Нажмите Commit changes. Откройте Actions и дождитесь успешной сборки и публикации. Если сборка завершилась ошибкой, прежняя опубликованная версия остаётся доступной; сохраните текст ошибки.
6. Откройте прежний адрес приложения. На ПК один раз обновите страницу с Ctrl+F5, на телефоне закройте и снова откройте вкладку. Адрес Google Apps Script остаётся тем же.

При сборке используется прежний формат протокола подключения, поэтому строку `GAS_TARGET_VERSION = 10` в сохранённом `src/config.ts` менять не нужно. Названия листов К10 тоже остаются. Новая оптимизация определяется отдельно автоматически.

### Если Source = Deploy from a branch

Используйте готовую сборку из `dist`, а не корневой `index.html` с исходным кодом Vite.

1. В Settings → Pages посмотрите, какая ветка и папка выбраны для публикации: например, main + `/ (root)` или main + `/docs`.
2. В этой папке замените опубликованный `index.html` файлом `dist/index.html` из архива. Сохраните его название `index.html`. Соседние файлы `dist/google-apps-script.js` и `dist/appsscript.json` можно положить туда же.
3. Сохраните изменения и дождитесь публикации Pages. Откройте прежний адрес сайта.
4. Если адрес таблицы раньше задавался через настройки приложения или ссылку `?script=...`, сохранённое подключение продолжит использоваться на прежних устройствах. Для нового устройства используйте существующую общую ссылку с `?script=...` или введите тот же `/exec` в настройках подключения.
5. Если адрес был жёстко встроен в прежний HTML, его нет в универсальной сборке. До массового обновления используйте прежний `/exec` через настройки подключения / ссылку `?script=...`, либо соберите исходники с вашим `gasUrl`. Не заменяйте адрес на URL самой Google Таблицы.

## 4. Проверка после установки

Сначала убедитесь, что на ПК и телефоне загружаются те же разделы и цены. Данные Google Таблицы должны остаться на прежних листах.

Когда можно кратко провести проверку, выберите одну заранее записанную тестовую ячейку, измените её из приложения и проверьте Google Таблицу и второе устройство. Затем верните исходное значение. Аналогично проверьте одну правку из самой Google Таблицы. Это уже ваши проверочные изменения, а не обязательная миграция.

При редактировании одной и той же ячейки двумя администраторами конфликт должен оставаться видимым и сохранять черновик. Независимые правки объединяются. Дождитесь завершения сохранений перед закрытием вкладок.

Изменения по-прежнему появляются автоматически после обработки и очередной проверки версии. Интервал проверки приложения сохранён: примерно 10–12 секунд плюс время ответа Google. Мгновенный push-канал в этой архитектуре не добавлялся.

## 5. Что ускорено и что осталось

- Свойства всех листов получаются одним запросом вместо отдельных обращений в цикле.
- Части кэша записываются пакетом и читаются пакетом.
- Для обычных правок новый клиент отправляет изменённые разделы, а не весь каталог. Сервер возвращает короткое подтверждение с необходимыми нормализациями.
- При фоновой загрузке изменившейся версии передаются изменённые разделы, если исходная версия ещё есть во временном кэше. При отсутствии кэша автоматически загружается полный каталог.
- Поиск строк перед записью использует индекс по ID.
- Перед записью актуальные рабочие листы всё ещё читаются и проверяются. Это сохраняет обнаружение ручной правки, даже если её триггер ещё не успел выполниться.
- Защита от конфликта, повторного запроса и незавершённого сохранения сохранена. Таблица — единственное постоянное хранилище; кэш можно потерять без потери данных.

## 6. Откат

1. Дождитесь завершения сохранений. При ошибке или несохранённом черновике сначала экспортируйте его из приложения. Не очищайте хранилище браузера.
2. В Apps Script верните **ваш сохранённый перед обновлением код**. Это восстановит старые обработчики триггеров.
3. В Управлении развертываниями выберите прежнюю версию существующего развёртывания и сохраните. URL `/exec` оставьте прежним.
4. На GitHub верните предыдущий коммит / ваши сохранённые файлы и дождитесь публикации.
5. Обновите страницы на устройствах. Восстанавливать старую копию Google Таблицы не нужно: это могло бы потерять новые товары и цены.

В папке `rollback` лежат исходный серверный код и готовый HTML из ранее выданного архива v10. Предпочтительнее ваша собственная копия, если после установки вы меняли конфигурацию или код.

## 7. Результаты проверки

Подробности — `AUDIT_REPORT.md`, машинные результаты — `test-results`.
Скорость действующего Google Apps Script в секундах не измерялась: сервер не обновлялся и рабочие данные не менялись. Браузерный запуск в среде подготовки заблокирован системным ограничением. Разметка и стили проверены автоматически по исходникам; интерактивную проверку после публикации пропускать не следует.
