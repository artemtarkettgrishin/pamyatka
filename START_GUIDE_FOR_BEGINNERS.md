# Версия 10: обычные Google-листы как основное хранилище

В этой версии каталог хранится **в строках и столбцах отдельных листов**. Приложение читает именно их. Рабочей JSON-копии каталога в ячейке больше нет. Старые листы версии 8/9 сохраняются скрытыми только как резерв переноса; после установки новые изменения в них не записываются.

Сохранена очередь отправки, восстановление черновиков и проверка конфликтов из рабочей версии 8. Убрана постоянная двусторонняя проекция версии 9. На телефоне товарная таблица остаётся **над** блоком декоров и подразделов.

## Обновление существующего приложения

1. Экспортируйте резервную копию каталога из приложения и сделайте копию самой Google Таблицы. Если есть несохранённый черновик, сначала сохраните или экспортируйте его. На время первоначального переноса закончите редактирование на телефонах, ПК и в ячейках.
2. В **той же** Google Таблице откройте «Расширения → Apps Script». Замените старый серверный код **полным содержимым `public/google-apps-script.js`**. Не оставляйте дубли старых функций в других `.gs` файлах. Пароль `ADMIN_PASSWORD` в свойствах проекта не меняйте.
3. **Новый обязательный шаг:** слева в Apps Script откройте «Сервисы → +», выберите **Google Sheets API**, версия **v4**, идентификатор **Sheets**, и добавьте сервис. Он нужен для общей пакетной записи изменений и версии. Если сервис уже добавлен, второй раз добавлять его не нужно. Для стандартного Google Cloud проекта может также потребоваться включить Google Sheets API в его Cloud Console.
4. В списке функций выберите **`installWorkbook` → Выполнить** под владельцем развёртывания. Разрешите запрошенный доступ. Дождитесь успешного выполнения. Скрипт перенесёт существующий каталог и создаст листы `К10 …`, а также три автоматических триггера.
5. Если выполнение завершилось ошибкой, не переходите к публикации: исправьте причину из журнала выполнения и повторите `installWorkbook`. Повторный запуск предусмотрен. Противоречивые правки старых листов версии 9 не отбрасываются молча: перенос остановится с описанием конфликта. Исходные данные не удаляются.
6. В Apps Script: **«Развернуть → Управление развёртываниями → Изменить → Новая версия → Развернуть»**. Обновляйте существующее развёртывание, сохраняя адрес `/exec`. Веб-приложение должно выполняться от имени владельца; просмотр по ссылке настраивается так же, как в рабочей версии 8.
7. Обновите приложение на прежнем сайте. Готовый файл находится в **`dist/index.html`**. Если URL сервера был прописан в `src/config.ts`, перенесите ваш действующий URL и выполните `npm ci`, затем `npm run build`. На уже подключённых устройствах сохранённый адрес остаётся в браузере.
8. Один раз обновите приложение на устройствах и переоткройте Google Таблицу. Откроется лист **`К10 Главное меню`**; сверху появится меню **«Каталог»**. Дальше изменения данных приходят без перезагрузки страницы.

Нужны **обе части обновления**: серверный скрипт и сайт. Файл `public/appsscript.json` приведён как образец манифеста с нужным сервисом и правами; при существующих дополнительных настройках проекта не заменяйте их вслепую — обычно достаточно шага 3.

## Как устроены листы

| Лист | Что в нём менять |
|---|---|
| `К10 Главное меню` | Верхние вкладки: «Обновления», «Линолеум», «Ламинат» и другие. Видимые поля ID, название, тип, порядок и настройки |
| `К10 Меню Линолеум · …` | Только прямые подразделы «Линолеума», например «Таркетт» |
| `К10 Меню Таркетт · …` | Коллекции внутри этого «Таркетта» |
| `К10 Меню Название коллекции · …` | Декоры и другие дочерние пункты этой коллекции |
| `К10 Товары Таркетт · …` | Собственная товарная таблица раздела «Таркетт», если данные вносятся на этом уровне |
| `К10 Товары Название коллекции · …` | Собственная таблица конкретной коллекции: по одному товару в строке, по одному параметру в столбце |
| `К10 Журнал Обновления · …` | Дата, раздел, текст обновления, важность, автор — отдельные колонки |
| `К10 Столбцы` | Настройка товарных колонок по ID раздела: название, ключ, ширина, цвет, закрепление |
| `К10 Пометки` | Сообщения над и под таблицами по ID раздела |
| `К10 Настройки` | Название приложения, валюта, ID стартового раздела |
| `К10 Навигатор` | Полный путь и имя каждого рабочего листа. Это справочник, его создаёт программа |
| `К10 Инструкция` | Краткие правила; строка 12 показывает результат фоновой проверки или ошибку |

Короткий суффикс в имени листа отличает одноимённые коллекции. Не нужно его придумывать: он формируется автоматически. Переименование раздела меняет имя листа; обычные правки ID и названия сохраняют связь с существующим листом.

Каждый раздел получает собственный лист дочернего меню; у конечного декора он пока будет пустым. На всех уровнях можно иметь собственную таблицу товаров. Это намеренная структура: уровни 2, 3, 4 и глубже не свалены в один общий список. Журналы разных вкладок тоже независимы.

## Пример: Линолеум → Таркетт → Коллекция → Декор

1. На `К10 Главное меню` добавьте строку: ID `linoleum`, название `Линолеум`, тип `Раздел`. Если такой раздел уже существует, используйте существующую строку.
2. Дождитесь появления `К10 Меню Линолеум · …`. В нём добавьте ID `tarkett`, название `Таркетт`, тип `Раздел`. Для новой строки родитель берётся из листа автоматически, если поле «ID родителя» пустое.
3. В `К10 Меню Таркетт · …` добавьте ID `collection_1`, название коллекции, тип `Страница`.
4. В `К10 Столбцы` создайте нужные колонки для ID `collection_1`, например `name` — «Наименование» и `price` — «Цена». Затем заполните строки в `К10 Товары Название коллекции · …`.
5. Для декора добавьте строку в меню коллекции. Его отдельные меню и таблица появятся автоматически.

Те же разделы можно создать через приложение на ПК или телефоне. В окне создания/редактирования есть поле **«ID раздела»**. Пустое поле при создании означает автоматический ID. Пользовательские ID должны быть уникальными.

## Правила редактирования

- **Название и ID:** меняйте в соответствующей строке меню. При смене ID раздела программа обновляет ссылки дочерних разделов, стартовых страниц, пометок, колонок и журналов. Внутренние скрытые ключи не редактируйте.
- **Перенос раздела:** укажите другой «ID родителя». Для существующего раздела очистка этого поля перемещает его в главное меню. Нельзя делать раздел собственным потомком.
- **Товар:** измените любую ячейку его таблицы. Пустое значение очищает поле, ноль сохраняется. Для новой строки можно задать ID товара самостоятельно или оставить его пустым.
- **Колонки:** меняйте через `К10 Столбцы`. Новые колонки появляются в нужной товарной таблице. Смена ключа колонки переносит значения; пересечение с другим заполненным ключом вызывает ошибку. Техническую строку ключей 3 не редактируйте.
- **Незавершённая строка:** например, колонка без ID раздела остаётся на листе как черновик. Завершите обязательные поля, и она будет принята.
- **Порядок:** используйте «Порядок». Сортировка всех колонок строки сохраняет принадлежность значений товару. Сортировка одного столбца отдельно от других перемешает данные, как в любой таблице.
- **Удаление:** поставьте «Да» в «Удалить». Для ветки меню отметьте также её дочерние пункты. Физическое удаление товарной строки тоже удаляет её из каталога: в этой версии лист является источником данных. Восстановление ошибочного ручного удаления — через отмену или историю Google Таблицы. Рабочие листы целиком не удаляйте.
- **Тип:** `Раздел`, `Страница`, `Журнал`. Журнал представляет самостоятельную вкладку обновлений. Для нового журнала верхнего уровня создайте соответствующую строку в главном меню.
- **Цвета/выравнивание:** используйте существующие значения приложения. Подсветка строк: `none`, `yellow`, `red`, `green`, `blue`. Выравнивание: `left`, `center`, `right`. Пометки: `danger`, `warning`, `info`, `success`, `accent`, `purple`.

## Синхронизация

Приложение проверяет версию примерно каждые 10–12 секунд плюс время ответа Google. Если изменений нет, сервер читает только номер версии и не перебирает товарные листы. Общая временная память ускоряет получение новой версии несколькими пользователями; её потеря не приводит к потере каталога — данные заново читаются из листов.

Правки из приложения записываются вместе с номером версии и квитанцией запроса одним пакетом Google Sheets API. Только изменённые ячейки и необходимые изменения структуры отправляются в таблицу. Повтор запроса после пропажи ответа не создаёт вторую запись.

Ручные правки обрабатывает установленный триггер. Если он задержался или был занят, изменения найдёт фоновая проверка, обычно в течение минуты. Меню **«Каталог → Проверить изменения»** ставит такой запрос. Для правок через сторонние скрипты/API и перерасчёта формул событие редактирования может отсутствовать; их обнаруживает фоновое чтение. Сложные формулы не входят в проверенную область этой версии.

При одновременных правках разных полей в приложениях они объединяются. При разных правках одного поля сохраняется конфликтный черновик. Перед отправкой из приложения сервер также проверяет изменения ячеек Google, даже если событие редактирования ещё не пришло.

**Граница возможностей Google:** ручное редактирование ячеек не подчиняется блокировке Apps Script. Есть повторная проверка изменяемых ячеек и ID строк перед записью, но абсолютной гарантии между этой проверкой и самой записью Google не предоставляет. Два человека, одновременно меняющие одну ячейку прямо в Google, получают последнее значение Google Sheets. Для спорных случаев используйте историю изменений. Атомарность пакета означает отсутствие частично выполненной серверной записи, а не блокировку ручного ввода.

## Если данные не обновляются

1. Посмотрите `К10 Инструкция`, строку 12, и «Выполнения» в Apps Script.
2. Убедитесь, что есть сервис `Sheets`, три триггера, опубликована новая версия того же `/exec`, сайт тоже обновлён.
3. Проверьте повторяющиеся ID, неправильного родителя, удалённые листы и изменённые служебные строки. Неверная структура не принимается молча: сайт сохранит локально показанные данные, а запись остановится до исправления.
4. Исправьте ячейку; сработает триггер. Либо запросите проверку через меню «Каталог».

Права редактирования самой Google Таблицы выдавайте только администраторам каталога. Сотрудникам для просмотра достаточно приложения. Вход администратора и проверка его прав на сервере сохранены.

## Проверка после установки

Откройте приложение на ПК и телефоне. Поменяйте разные цены одного товара на двух устройствах и дождитесь обеих правок. Затем измените название товара в его Google-листе — открытые приложения должны получить изменение. Создайте тестовый раздел и вложенный декор: проверьте их отдельные листы. На телефоне товарная таблица должна быть выше блока декоров.

В этой поставке проверен исходный код, модель Google API и браузеры. Ваш действующий `/exec` не предоставлен; реальное развёртывание и скорость ответа Google после установки нужно проверить указанными действиями.
